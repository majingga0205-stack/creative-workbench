# 창작 작업대 — 클로드 코드용 기능 명세

2026년 11월 25일 · @마정우

## 개요와 원칙

창작 작업대는 혼자 쓰는 로컬 웹앱으로, 다섯 모듈(시대 고증 린터 · 인물 네트워크 · 연재 실험실 · 신화 원형 아카이브 · 보스 페이즈 설계 보드)을 작품 단위로 묶는다. AI나 외부 API 없이 규칙 기반으로만 동작하고, 데이터는 내 컴퓨터에만 저장한다. 웹앱으로 먼저 완성하고, 다듬은 뒤 데스크톱 앱 전환을 검토한다.

클로드 코드가 모든 단계에서 지킬 원칙:

1. **오프라인 규칙 기반** — LLM API, 외부 서버 호출, 원격 CDN·폰트 없음. 모든 판정은 이 문서에 적힌 공식과 사용자가 바꿀 수 있는 설정값으로만 한다.
2. **데이터 보존이 새 기능보다 우선** — 저장 구조를 바꿀 땐 마이그레이션 필수, 삭제·덮어쓰기 전 확인, 불러오기 전 자동 백업.
3. **출처 무결성** — 고증·신화 데이터의 출처를 지어내지 않는다. 예시 데이터는 전부 '미검증'으로 넣고, 사용자가 원문을 직접 확인해야 '검증됨'으로 바뀐다.
4. **경고는 지적이지 금지가 아니다** — 모든 경고에 '의도함 / 무시' 처리를 둔다. 창작상 일부러 바꾼 설정을 막지 않는다.
5. **핵심 로직은 UI와 분리** — 판정·계산은 순수 함수로 만들고 테스트를 붙인다.
6. **화면 문구는 한국어**.

이번 버전 범위 밖: 희곡 파싱, 막별 넘겨보기, 판본별 원형 카드, 보스 템플릿, AI 연동, 데스크톱 패키징. 나중에 붙일 수 있도록 입력 경로와 데이터 구조만 열어 둔다.

## 기술 스택과 폴더 구조

프런트엔드만으로 돌아가는 React + Vite 앱이고, 서버는 두지 않는다. 모든 라이브러리는 npm으로 설치해 로컬에 번들한다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 화면 | React + Vite + TypeScript | 개연성 검토기와 같은 계열 |
| 스타일 | Tailwind CSS | 빠른 화면 조립 |
| 상태 | Zustand | 가볍고 모듈별로 나눠 쓰기 쉬움 |
| 저장 | IndexedDB + Dexie | 브라우저 안 로컬 DB, 원고 같은 긴 텍스트도 저장 가능 |
| 입력 검사 | zod | JSON 불러오기·마이그레이션 검사 |
| 관계 그래프 | Cytoscape.js | 네트워크 그리기 + 중심성 계산 내장 |
| 차트 | Recharts | 리듬 파형, 연독률, 긴장도 곡선 |
| 2D 미리보기 | HTML Canvas 직접 구현 | 게임 엔진 없이 충분 |
| 텍스트 비교 | jsdiff (`diff` 패키지) | 원고 버전 비교 |
| 내보내기 | html-to-image(PNG), 인쇄용 CSS → 브라우저 PDF 저장 | 오프라인 유지 |
| 테스트 | Vitest | `src/core` 로직 단위 테스트 |
| 폰트 | Pretendard (npm 로컬 번들) | 원격 폰트 금지 원칙 |

형태소 분석기는 쓰지 않는다. 고증·인물 매칭은 '표제어 + 조사' 규칙 매처로 충분하고(공통 항목 참고), 나중에 Kiwi 같은 분석기를 오프라인으로 붙일 수 있게 매처를 인터페이스로 분리한다.

```
creative-workbench/
├─ CLAUDE.md
├─ docs/
│  ├─ SPEC.md            ← 이 문서를 Markdown으로 내보내 저장
│  ├─ PROJECT_STATE.md   ← 단계가 끝날 때마다 갱신
│  └─ TODO.md
└─ src/
   ├─ core/              ← 순수 로직 (React·DB import 금지)
   │  ├─ korean/         문장 분리, 조사 인식 매처, 정규화
   │  ├─ lint/           고증 판정
   │  ├─ rhythm/         리듬 지표, 엔딩 유형 추정, 가설 비교
   │  ├─ network/        동시 등장 집계, 인물 빼기 실험
   │  ├─ archetype/      원형 보존도, 충돌·함정 검사
   │  └─ boss/           타이밍, 압박도, 충돌 판정, 시뮬레이션
   ├─ db/                Dexie 스키마, 마이그레이션, 백업
   ├─ modules/           lint · network · serial · myth · boss 화면
   ├─ shared/            공용 컴포넌트, 작품 선택기
   └─ seed/              예시 데이터 (전부 미검증)
```

테스트 파일은 대상 옆에 `*.test.ts`로 둔다.

## 공통 기능

작품이 최상위 단위이고, 캐릭터와 회차 원고는 여러 모듈이 같이 쓰는 공유 데이터다. 고증 DB와 신화 DB는 작품과 상관없는 공용 라이브러리다.

### 데이터 범위

| 데이터 | 범위 | 쓰는 모듈 |
|---|---|---|
| 작품(시대 설정, 세계관 용어집 포함) | 작품 | 전부 |
| 캐릭터(이름, 별칭, 특성, 연결된 원형) | 작품 | 인물 네트워크, 신화 아카이브, 보스 보드 |
| 회차 원고(버전 여러 개) | 작품 | 연재 실험실, 고증 린터, 인물 네트워크 |
| 독자 지표, 가설 | 작품 | 연재 실험실 |
| 보스·페이즈·패턴 | 작품 | 보스 보드 |
| 고증 항목 | 공용 | 고증 린터 |
| 신화 존재·원형 요소·함정 | 공용 | 신화 아카이브 |

```ts
type Work = { id: string; title: string; kind: '소설' | '게임' | '기타';
  setting?: { label: string; yearFrom: number; yearTo: number; region: string };
  createdAt: string; updatedAt: string };
type Character = { id: string; workId: string; name: string; aliases: string[];
  archetypeId?: string; traits: string[]; note: string };
type Chapter = { id: string; workId: string; number: number; title: string;
  versions: { id: string; label: string; text: string; createdAt: string }[];
  activeVersionId: string; publishedAt?: string;
  endingTag?: '절단' | '여운' | '정리'; endingTagSource?: 'auto' | 'user' };
```

### 한국어 텍스트 코어 (`src/core/korean`)

- **원문 위치 보존**: 모든 지적과 매칭 결과는 원문 기준 `start`/`end` 글자 위치를 갖는다. 키워드로 다시 찾아 하이라이트하지 않는다. 분석용 정규화를 하더라도 위치 대응표를 남긴다.
- **조사 인식 매처** `matchTerm(text, term, options)`: 표제어 앞이 한글 음절이 아니고, 뒤가 끝·공백·문장부호이거나 허용 조사(이/가/을/를/은/는/의/에/에서/에게/한테/로/으로/와/과/도/만/까지/부터/처럼/보다/이나/나/랑/이랑/하고, 서술격 다/이다/였/이었/인)로 시작해야 매칭. 조사 목록은 설정에서 고칠 수 있다.
- **매칭 모드**: `word`(기본, 조사만 허용) / `prefix`(‘감자밭’처럼 복합어 앞부분도 매칭). 항목별 예외 목록으로 오탐을 막는다(예: ‘경제’ 항목의 예외 ‘경제육전’).
- **문장 분리** `splitSentences(text)`: 줄바꿈은 항상 경계, 그 안에서는 `. ! ? … ...`(뒤에 붙은 닫는 따옴표 포함) 뒤에서 나눈다. 따옴표(“ ”, " ", 「 」, 『 』) 안 문장은 `isDialogue: true`.
- **장면 분리** `splitScenes(text)`: 단독 줄 구분선(`***`, `* * *`, `---`, `◆`, `◇` 등, 설정 가능) 기준.

### 모듈 간 연결

- 회차 원고 하나를 연재 실험실에 올리면 고증 린터와 인물 네트워크가 같은 원고를 바로 쓴다. 다시 붙여넣지 않는다.
- 캐릭터 하나가 인물 네트워크의 노드, 신화 아카이브의 대조 대상, 보스 보드의 보스 주인이 된다.
- 지적에서 원본으로 이동한다: 고증 지적 → 해당 회차의 그 위치, 네트워크 노드 → 캐릭터 카드, 보스 → 연결된 캐릭터.

회차 원고와 캐릭터는 각각 세 모듈이 함께 쓰므로, 이 둘의 구조는 1단계에서 확정하고 나중에 바꿀 땐 마이그레이션을 거친다.

### 저장·백업

- 입력 후 0.5초 뒤 자동 저장. 모든 레코드에 `updatedAt`.
- 시작할 때 `navigator.storage.persist()`를 요청한다. 브라우저 데이터를 지우면 사라질 수 있으므로 마지막 백업 후 7일(설정 가능)이 지나면 상단에 알림.
- **내보내기**: 전체 / 작품 하나 / 고증 DB만 / 신화 DB만. 형식 `{ app: 'creative-workbench', schemaVersion, exportedAt, scope, data }`.
- **불러오기**: zod 검사 → 미리보기(추가·변경·충돌 개수) → '합치기'(같은 id는 `updatedAt` 최신 우선, 충돌은 목록으로 보여줌) 또는 '교체' 선택 → 실행 전에 현재 데이터를 자동 백업 파일로 저장.
- 스키마 버전이 낮은 파일은 마이그레이션을 거쳐 불러온다. 높은 파일은 거부하고 이유를 보여준다.

## 모듈 A — 시대 고증 린터

작품이나 회차에 시대를 정하고 원고를 검사하면, 아직 없던 것은 빨강, 시점이 경계에 걸리거나 이설이 있는 것은 노랑, 뜻이 바뀐 단어는 파랑으로 원문에 표시한다.

### 데이터 모델

```ts
type LintEntry = {
  id: string; term: string; aliases: string[];
  matchMode: 'word' | 'prefix'; exclude: string[];
  category: '물건' | '음식' | '제도' | '단어' | '개념' | '호칭' | '기타';
  kind: 'not_yet' | 'meaning_shift';
  region: string;                                   // '한반도', '중국', '서양', '전체' …
  appears?: { from: number; to: number; precision: '연도' | '시기' | '세기' }; // not_yet
  senses?: { label: string; from?: number; to?: number; contextWords: string[] }[]; // meaning_shift
  sources: { title: string; author?: string; year?: string; locator?: string;
    type: '1차 사료' | '연구서·논문' | '사전' | '기타'; url?: string }[];
  disputed: boolean; disputeNote?: string;
  verified: boolean;     // 사용자가 출처 원문을 직접 확인했는가
  note?: string; updatedAt: string;
};
```

### 판정 규칙

시대 설정은 `yearFrom`~`yearTo`와 지역이다. 작품 기본값을 회차에서 덮어쓸 수 있다. '조선 중기' 같은 시대 이름은 학자마다 구분이 달라서, 프리셋은 연도 범위를 고칠 수 있는 기본값으로만 둔다.

| 조건 (`not_yet`) | 표시 |
|---|---|
| `yearTo` < `appears.from` (설정 시대 전체가 등장 이전) | 빨강 '없던 것' |
| 설정 범위와 `appears` 범위가 겹침 | 노랑 '경계' |
| `yearFrom` ≥ `appears.to` | 표시 안 함 |
| `disputed: true` | 색과 별도로 '이설 있음' 배지 |
| `verified: false` | 색과 별도로 '미검증' 배지 |

- 항목은 `region`이 설정 지역과 같거나 '전체'일 때만 적용한다.
- `meaning_shift`는 찾으면 파랑 '뜻 확인'으로 표시하고, 설정 시대에 통하던 뜻을 보여준다. 앞뒤 30자 안에 현대 뜻의 `contextWords`가 있으면 노랑 '현대 뜻으로 쓴 듯함'으로 올린다.
- 처리 상태: 미처리 / 의도함 / 무시(이 위치만 · 이 회차 · 이 작품 전체). 처리 기록은 남기고 리포트에 포함한다.

### 화면

- 왼쪽은 하이라이트된 원고, 오른쪽은 지적 목록(색·종류·회차·처리 상태 필터). 지적을 누르면 항목 카드(시기, 근거 사료, 이설 메모, 검증 여부)가 열린다.
- 검사 대상은 붙여넣은 텍스트 또는 작품의 회차(현재 버전). 여러 회차를 한꺼번에 검사할 수 있다.

### 고증 DB 편집기

- 목록(검색, 분류·종류·검증 여부 필터)과 편집 폼.
- 저장 조건: 출처 1개 이상, `not_yet`은 `appears`, `meaning_shift`는 뜻 2개 이상.
- `verified`는 '원문에서 직접 확인함'에 사용자가 체크할 때만 켜진다. 출처를 고치면 다시 꺼진다.
- 예문 테스트 칸: 문장을 넣으면 이 항목이 매칭되는지 바로 보여줘서 오탐을 잡는다.

### SF 세계관 모드

```ts
type GlossaryEntry = { id: string; workId: string; canonical: string; variants: string[];
  status: '사용' | '금지'; replacement?: string; note?: string };
```

- 금지어(이 세계에 없는 것, 예: 스마트폰) → 빨강 + 대체어 제안.
- 표기 흔들림: 정식 표기가 아닌 `variants`를 찾으면 노랑 + 정식 표기 안내(예: ‘나노 팔찌’ → ‘나노테크 팔찌’).
- 시대 판정과 따로 켜고 끌 수 있다. 용어집은 작품별로 저장한다.

### 검사 리포트

Markdown과 인쇄용 HTML(브라우저에서 PDF로 저장)로 내보낸다. 내용은 작품·회차·설정 시대·검사일, 색별 개수, 지적마다 [회차 · 앞뒤 20자 발췌 · 항목 · 시기 · 근거 · 검증 여부 · 처리 상태].

| 경제 | meaning_shift | 조선: 세상을 다스리고 백성을 구제함 / 근대 이후: economy | 『경제육전』(1397) 등 조선 전기 용례, 근대 번역어 연구 | 현대 뜻 문맥어: 돈, 시장, 물가, 불황 / 예외: 경제육전 |

## 모듈 B — 인물 네트워크

회차 원고에서 등록된 캐릭터가 같은 장면에 함께 나온 횟수를 세어 관계망을 그리고, 중심성과 '인물 빼기' 실험으로 이야기 구조를 본다. 이번 버전의 입력은 내 소설 회차다. 희곡은 나중에 붙일 수 있게 입력 부분을 어댑터로 분리한다.

### 집계 규칙

- **인물 인식**: 캐릭터의 이름과 별칭을 공통 매처(`word` 모드)로 찾는다. ‘연구원’ 같은 호칭 별칭은 오탐이 있어서, 별칭마다 '같은 장면에 본명이 나왔을 때만 인정' 옵션을 둔다.
- **단위**: 장면(`splitScenes`). 구분선이 없는 회차는 문단 8개씩 끊은 구간을 장면으로 본다(설정 가능).
- **간선 가중치**: 두 인물이 함께 나온 장면 수. 같은 문단에 함께 나오면 더하는 추가 가중치는 설정값(기본 0).
- **범위**: 회차 범위를 고른다(예: 1~10화).
- **수동 보정**: 간선 추가·삭제와 관계 라벨(가족·동료·적대 등 자유 입력). 계산 결과와 따로 저장해서 다시 계산해도 유지한다.

### 관계 그래프

- Cytoscape.js, `cose` 레이아웃. 노드 크기 = 등장 장면 수, 간선 굵기 = 가중치, 노드 색 = 고른 중심성 지표.
- 노드를 누르면 캐릭터 카드와 등장 회차 목록. 그래프는 PNG로 저장할 수 있다.

### 중심성 지표

| 지표 | 계산 | 읽는 법 |
|---|---|---|
| 연결 정도(가중) | 간선 가중치 합 | 누가 가장 많은 인물과 얽히나 |
| 매개 중심성 | 다른 인물 사이 최단 경로에 끼는 비율 | 집단과 집단을 잇는 연결 고리 |
| 근접 중심성 | 모든 인물까지의 평균 거리의 역수 | 이야기의 한가운데에 있는 인물 |

- 최단 경로는 가중치를 '거리'로 쓰므로 거리 = 1 / 가중치로 넣는다(자주 함께 나올수록 가까움).
- **존재감 하락 경고**: 전체 등장 상위 30% 인물 중 최근 5화(설정 가능) 등장 비율이 그 전 평균의 절반 아래로 떨어진 인물을 표시한다.

### 인물 빼기 실험

- 인물을 고르면 그 노드를 뺀 그래프로 다시 계산해 전후를 비교한다: 연결 요소(조각) 수, 고립되는 인물, 평균 최단 경로, 남은 인물의 중심성 순위 변화.
- 결과는 문장으로도 보여준다: “OO를 빼면 관계망이 두 조각으로 나뉘: {A, B} / {C, D, E}”.
- **일괄 실험**: 모든 인물을 하나씩 빼 본 표. 빼면 관계망이 쪼개지는 인물이 구조상 빠질 수 없는 인물이다.
- 프랑코 모레티가 『햄릿』의 인물 네트워크로 플롯을 분석한 방식(2011)을 내 소설에 적용하는 기능이다.

## 모듈 C — 연재 실험실

회차 원고의 리듬을 자동으로 재고, 직접 입력한 독자 지표와 나란히 놓아 가설을 검증한다. 연재 전에는 같은 회차의 버전(예: 수정 전 · 개선1)을 비교하는 데 바로 쓸 수 있다.

### 원고 입력

- 붙여넣기 또는 .txt 불러오기. UTF-8로 읽고, 깨지면 EUC-KR로 다시 읽는다(`TextDecoder('euc-kr')`).
- 회차마다 버전을 여러 개 두고, 현재 버전 하나를 다른 모듈이 쓴다.

### 리듬 지표 (버전마다 자동 계산)

| 지표 | 계산 | 보여주는 곳 |
|---|---|---|
| 글자 수 | 공백 포함·제외 둘 다 | 회차 카드 |
| 문장 길이 파형 | 문장마다 공백 제외 글자 수 + 5문장 이동 평균 | 선 그래프(x = 문장 순서), 대사 문장은 점 색을 다르게 |
| 문장 길이 통계 | 평균, 중앙값, 표준편차, 짧은 문장(15자 이하)·긴 문장(60자 이상) 비율 | 표, 기준값 설정 가능 |
| 대사 비율 | 대사 글자 수 ÷ 전체 글자 수, 문장 수 기준도 함께 | 막대 |
| 문단 길이 | 문단(줄바꿈 또는 빈 줄 단위, 설정) 글자 수 분포, 200자 넘는 '벽 문단' 위치 | 히스토그램 + 원고에 표시 |
| 문장부호 | `!` `?` `…` 로 끝나는 문장 비율 | 표 |

회차마다의 지표는 한 표와 선 그래프(x = 회차)로도 본다.

### 마지막 문단 유형

- 태그는 절단 / 여운 / 정리. 최종 태그는 사용자가 고른다.
- 자동 추정은 참고용이고 근거를 함께 보여준다. 절단 = 마지막 문장이 대사이거나 `? ! … —`로 끝나거나 20자 이하, 정리 = 마지막 문단이 서술이고 80자 이상, 여운 = 그 밖. 기준값은 설정에서 바꾼다.

### 독자 지표와 연독률

- 지표 항목은 사용자가 정한다(플랫폼마다 다름). 기본은 조회수·댓글 수.
- 입력은 스냅샷 단위다: 회차, 값, 기록일, 게시 후 일수. 조회수는 시간이 지나면 쌓이므로 비교는 '게시 후 같은 일수' 스냅샷끼리 한다(기본 3일차). 없으면 가장 가까운 스냅샷을 쓰고 '기준 다름'을 표시한다.
- 연독률: 1화 대비 = 조회(n) ÷ 조회(1), 직전 대비 = 조회(n) ÷ 조회(n−1).
- 직전 대비 연독률이 전체 중앙값보다 10%p 이상 낮은 회차를 '꺾이는 구간'으로 강조한다(기준 설정 가능).
- 그래프: 조회수 선 + 직전 대비 연독률 막대, 회차 점 모양으로 엔딩 태그를 구분한다.

### 가설 기록·결과 확인

```ts
type Hypothesis = { id: string; workId: string;
  statement: string;                      // "엔딩을 끊어 치면 다음 화 유지율이 오른다"
  condition: { field: 'endingTag' | 'dialogueRatio' | 'length' | 'custom';
               op: '=' | '>' | '<'; value: string | number };
  metric: string; target: 'same' | 'next'; // 비교할 지표, 같은 화인가 다음 화인가
  checkAfterChapter: number;
  status: '대기' | '확인할 때 됨' | '지지됨' | '기각' | '보류';
  resultNote?: string; createdAt: string };
```

- 조건에 맞는 회차 집단과 나머지의 지표 평균·중앙값을 나란히 보여주고 표본 수를 함께 적는다. 엔딩 관련 가설은 다음 화 지표가 기본이다.
- 한쪽 집단이 5화 미만이면 '표본 부족 — 참고만' 배지를 붙이고, 함께 움직인다고 원인은 아니라는 안내를 한 줄 둔다.
- 확인 회차의 지표가 입력되면 상단에 '확인할 가설 N개' 알림이 뜬다.
- 지지·기각 판정은 사용자가 누른다. 앱은 숫자만 보여준다.

### 원고 버전 비교

- 같은 회차의 버전 두 개를 고르면 지표 차이 표(증감 색 표시), 문장 길이 파형 겹쳐 보기, 본문 차이(jsdiff, 문장 단위 추가·삭제·변경)를 보여준다.
- 다른 회차끼리도 지표는 비교할 수 있다(본문 차이는 제외).

## 모듈 D — 신화 원형 아카이브

신화·설화 존재마다 원형 요소를 체크리스트로 쌓고, 내 캐릭터를 대조해 가져온 것·바꾼 것·버린 핵심·충돌을 보여준다. 판본별 카드는 범위 밖이라 출처는 요소 하나하나에 단다.

### 데이터 모델

```ts
type Being = { id: string; name: string; aliases: string[]; summary: string;
  elements: ArchetypeElement[]; traps: Trap[]; updatedAt: string };
type ArchetypeElement = { id: string; label: string;
  category: '외형' | '능력' | '성격' | '금기·약점' | '서사 기능' | '출현 장소';
  weight: 'core' | 'common' | 'variant';   // 핵심 3 · 흔함 2 · 일부 판본 1
  keywords: string[];   // 캐릭터 특성에서 이 요소를 알아볼 말
  opposite: string[];   // 이 요소와 정면으로 어긋나는 말
  sources: Source[]; verified: boolean; note?: string };
type Trap = { id: string; claim: string; correction: string; triggerWords: string[];
  sources: Source[]; verified: boolean };
type BeingRelation = { id: string; fromId: string; toId: string; label: string; sources: Source[] };
// Source는 고증 린터와 같은 타입을 공유한다.
```

### 원형 요소 체크리스트

- 존재 화면에 요소를 범주별로 나열하고, 가중치·출처·검증 여부를 배지로 보여준다.
- 출처 없이도 저장은 되지만 '출처 없음' 배지가 붙고, 대조 결과에서 회색으로 보인다.

### 내 캐릭터 대조

- 캐릭터를 존재에 연결하면(`Character.archetypeId`) 요소마다 가져옴 / 변형함 / 버림 을 고른다. 캐릭터 특성에 `keywords`가 있으면 '가져옴', `opposite`가 있으면 '충돌'을 자동 제안하고, 확정은 사용자가 한다.
- 어느 요소에도 걸리지 않은 캐릭터 특성은 '새로 더함'으로 묶는다.
- 결과는 네 칸이다: 가져온 것 / 바꾼 것 / 버린 핵심 요소 / 원형과 충돌. 충돌과 버린 핵심은 '의도함'으로 정리할 수 있다.
- 보존도는 아래 식으로 계산하고, 높을수록 좋은 점수가 아니라 '원형에 얼마나 기대나'를 뜻한다고 화면에 적는다.

$$
\text{보존도} = \frac{\sum_{\text{가져옴}} w + 0.5 \sum_{\text{변형함}} w}{\sum_{\text{전체 요소}} w}, \quad w_{\text{core}}=3,\ w_{\text{common}}=2,\ w_{\text{variant}}=1
$$

### 고증 함정 경고

- 캐릭터 특성이나 설명에 `triggerWords`가 나오면 경고 카드를 띄운다: 흔한 오해 → 바로잡은 내용 → 근거.
- 예: 도깨비 + ‘뿔’·‘호피’·‘쇠몽둥이’ → “뿔이 나고 호랑이 가죽을 두르고 쇠몽둥이를 든 모습은 일본 오니 이미지의 영향이라는 지적이 많다. 요술 방망이 자체는 한국 설화에도 나온다.” ‘방망이’는 트리거에 넣지 않는다.

### 존재 간 관계 그래프

- 인물 네트워크의 Cytoscape 컴포넌트를 재사용한다. 존재 노드 위에 현재 작품의 캐릭터를 다른 모양으로 겹쳐, 내 캐릭터가 어느 원형에 기대는지 보여준다.
- 관계 라벨은 자유 입력이고 출처를 달 수 있다.

### 시드 데이터 (전부 `verified: false`)

아래는 널리 알려진 특징만 적은 예시다. 출처 칸은 비워 두고, 국립민속박물관 『한국민속대백과사전』 등에서 확인한 뒤 채운다. 클로드 코드는 이 목록 밖의 존재·요소·출처를 만들지 않는다.

| 존재 | 요소 (가중치) | 함정 |
|---|---|---|
| 구미호 | 꼬리 아홉 달린 여우(core), 사람·주로 여인으로 둔갑(core), 사람의 간이나 정기를 노림(common), 여우 구슬(common) | — |
| 도깨비 | 사람 손때 묻은 낡은 물건이 변함(common), 요술 방망이(common), 씨름·내기를 좋아함(common), 도깨비불(common), 메밀묵을 좋아함(variant) | 뿔·호피·쇠몽둥이 차림 (위 예시) |
| 산군(호랑이) | 산신 또는 산신의 사자로 모셔짐(core), 산신도에 산신과 함께 그려짐(common) | — |

## 모듈 E — 보스 페이즈 설계 보드

보스 전투를 페이즈 카드로 설계하고, 패턴마다 전조·공격·후딜 타이밍을 넣으면 앱이 압박도를 계산해 '의도한 긴장도'와 겹쳐 보여주고, 2D 미리보기로 실제로 피할 수 있는지 확인한다.

### 데이터 모델

```ts
type Boss = { id: string; workId: string; name: string; characterId?: string;
  arena: { width: number; height: number; shape: 'rect' | 'circle' };   // px
  player: { maxHp: number; speed: number; radius: number;               // px/s, px
    dodge: { distance: number; durationMs: number; iframeMs: number; cooldownMs: number } };
  phases: Phase[]; updatedAt: string };
type Phase = { id: string; order: number; name: string;
  emotion: string;            // 예: '부정', '분노'
  narrative: string;          // 이 페이즈가 전할 감정과, 그걸 메커닉으로 어떻게 보여주나
  weapon: string; hpFrom: number; hpTo: number;   // 체력 구간(%)
  transition: string;         // 다음 페이즈로 넘어가는 조건·연출
  intendedTension: number;    // 0~10, 설계자가 의도한 긴장도
  sequence: { patternId: string; weight: number }[];   // 패턴 출현 비중
  patterns: Pattern[] };
type Pattern = { id: string; name: string;
  shape: 'projectile' | 'arc' | 'thrust' | 'area' | 'dash';
  telegraphMs: number; activeMs: number; recoveryMs: number; cooldownMs: number;
  damage: number; counter: '회피' | '패링' | '방어' | '점프' | '기타';
  params: Record<string, number | string>;   // 모양별, 아래 표
  line?: string;              // 패턴 전에 보스가 하는 대사
  note?: string };
```

| 모양 | params | 예 |
|---|---|---|
| projectile | count, spreadDeg, speed, intervalMs, aim(player · fixed · spiral), angleDeg, radius | 활 탄막 |
| arc | radius, angleDeg, direction(player · fixed) | 검 휘두르기 |
| thrust | length, width | 창 찌르기 |
| area | form(circle · rect), size, at(player · boss) | 내려찍기 |
| dash | distance, width | 돌진 |

### 페이즈 카드

- 카드에 이름, 감정, 서사 메모, 무기, 체력 구간, 전환 조건, 의도한 긴장도 슬라이더, 패턴 칩, 대사를 넣는다.
- 카드는 끌어서 순서를 바꾸고 복제할 수 있다.
- 카드 아래에 계산값 요약: 패턴 수, 평균 후딜(반격 기회), 압박도.

### 패턴 타이밍 편집

- 패턴마다 가로 막대 하나: 전조 → 공격 → 후딜 → 쿨다운. 구간 끝을 끌거나 ms를 직접 입력한다.
- 페이즈 타임라인: 시퀀스를 비중대로 30초 분량 펼쳐 보여준다. 난수는 고정 시드라 매번 같은 배열이 나온다.
- 경고(기준값 조정 가능): 전조 250ms 미만 = 반응하기 어려움, 후딜 0 = 반격 기회 없음.

### 압박도와 긴장도 곡선

페이즈마다 압박도를 0~10으로 계산한다. 아래는 초기 공식이고, 가중치와 기준값은 설정 화면에서 바꾼다. 각 항은 시퀀스 비중으로 가중 평균한 패턴 값으로 계산하고 0~1로 자른다.

$$
\text{압박도} = 10\,(0.35D + 0.25R + 0.25H + 0.15P)
$$

- D(공격 밀도) = 공격 시간 ÷ 패턴 한 주기(전조+공격+후딜+쿨다운)
- R(반응 압박) = (1000 − 전조ms) ÷ (1000 − 250)
- H(피해) = 패턴 피해 ÷ 플레이어 최대 체력
- P(반격 기회 부족) = 1 − 후딜ms ÷ 1000

곡선 화면은 x = 페이즈 순서, 선 두 개(의도한 긴장도, 계산된 압박도)이고 점 아래에 감정 라벨을 단다. 두 값이 2 이상 벌어지면 '의도보다 쉬움/어려움'으로 강조하고, 감정은 높이되 압박은 낮추는 식의 의도적 어긋남은 '의도함'으로 표시한다.

### 2D 패턴 미리보기

- Canvas 탑뷰(기본). 보스는 아레나 중앙, 플레이어 더미 하나.
- 재생: 패턴 하나 반복 / 페이즈 시퀀스. 속도 0.25×~2×, 일시정지, 한 프레임씩 넘기기.
- 판정 범위는 전조 중엔 반투명 윤곽, 공격 중엔 채운 도형으로 그린다.
- 직접 조작: WASD 이동, Space 회피(무적 시간 포함). 피격 수와 받은 피해를 센다.
- **피할 수 있나 검사**: 패턴마다 보스와의 거리 3가지(가까움·중간·멀음)에서, 전조 시간 안에 걸어서 범위 밖으로 나갈 수 있는지, 또는 회피 무적으로 공격 시간을 넘길 수 있는지 기하 계산으로 판정해 ✓/✗로 보여준다.
- 시뮬레이션은 `src/core/boss`의 고정 간격(1/60초) 스텝 함수로 만들고, Canvas는 그리기만 한다.

### 기획서 내보내기

- 인쇄용 A4 가로 페이지: 표지(보스 이름·작품), 긴장도 곡선, 페이즈 카드(서사·무기·패턴 표), 패턴 타이밍 막대, 패턴마다 전조·공격 장면 스냅샷.
- PNG 일괄 저장(html-to-image), PDF는 브라우저 인쇄로 저장한다.
- 보스 하나만 JSON으로 내보내고 불러올 수 있다(팀원과 주고받기용).

9단계로 나눠 단계마다 프롬프트 하나씩 넣고, 직접 실행해 완료 조건을 확인한 뒤 다음으로 넘어간다. 시작 전에 이 문서를 Markdown으로 내보내 `docs/SPEC.md`로, 아래 'CLAUDE.md 초안'을 프로젝트 맨 위 `CLAUDE.md`로 저장한다.

1. 프로젝트 뼈대와 공통 기능

### 1단계 — 프로젝트 뼈대와 공통 기능

```
docs/SPEC.md 전체와 CLAUDE.md를 읽어줘. 이번엔 개발 1단계(프로젝트 뼈대와 공통 기능)만 해.

1. Vite + React + TypeScript 프로젝트를 만들고 SPEC '기술 스택' 표의 라이브러리를 설치해.

먼저 만들 파일 목록과 순서를 보여주고 진행해.
완료 조건: 작품 2개에 회차를 넣고 전체 내보내기 → 브라우저 데이터 삭제 → 불러오기를 하면 그대로 복원된다.

### 2단계 — 한국어 텍스트 코어

```
SPEC '한국어 텍스트 코어'를 src/core/korean에 순수 함수로 구현해줘: matchTerm(조사 인식, word/prefix 모드, 예외 목록), splitSentences(대사 표시 포함), splitParagraphs, splitScenes. 모든 결과는 원문 기준 start/end를 갖는다.

Vitest 테스트를 먼저 쓰고 구현해. 최소한 이 경우들을 포함해:
- '감자를 캐다' → '감자' 매칭(조사 '를')
- '감자밭' → word 모드에서는 안 됨, prefix 모드에서는 매칭
- '푼고추' → '고추'는 안 됨(앞이 한글), 별칭에 '푼고추'를 넣으면 매칭
- '경제육전' 예외 → '경제' 매칭 안 됨
- 대사 안 마침표, 말줄임표(... 와 …), 닫는 따옴표 뒤 문장 경계
- 줄바꿈만 있는 웹소설식 원고, 빈 줄로 문단을 나눈 원고

완료 조건: npm test 통과, 화면 변경 없음.
```

### 3단계 — 연재 실험실

```
SPEC '모듈 C — 연재 실험실'을 구현해줘. 계산은 src/core/rhythm(테스트 포함), 화면은 src/modules/serial.

완료 조건: 같은 회차에 버전 2개를 넣으면 지표 차이·파형 겹침·본문 차이가 보이고, 지표를 넣은 회차가 5개 이상이면 연독률 그래프와 꺾이는 구간이 표시된다.

## CLAUDE.md 초안

프로젝트 맨 위에 `CLAUDE.md`로 저장하면 클로드 코드가 대화를 시작할 때마다 읽는다. 위 원칙을 매번 프롬프트에 다시 쓸 필요가 없어진다.

```markdown
# 창작 작업대 — 작업 규칙

## 먼저 읽을 것
- docs/SPEC.md — 이번에 작업할 단계의 섹션
- docs/PROJECT_STATE.md — 지금까지 한 일과 알려진 문제

## 절대 규칙
1. 오프라인: 네트워크 요청, LLM·외부 API, 원격 CDN·폰트를 쓰지 않는다. 라이브러리는 npm으로만 설치한다.
2. 데이터 보존: DB 구조를 바꾸면 schemaVersion을 올리고 마이그레이션을 쓴다. 기존 데이터를 지우거나 덮어쓰는 동작은 확인 창 없이 실행하지 않는다.
3. 출처: 고증·신화 데이터의 항목, 연도, 출처를 지어내지 않는다. 시드는 SPEC 표에 있는 것만, 전부 verified: false.
4. 판정·계산은 src/core에 순수 함수로 두고 React·Dexie를 import하지 않는다. core를 바꾸면 테스트도 함께 고친다.
5. 하이라이트는 원문 start/end 위치로 한다. 키워드를 다시 찾아 위치를 추정하지 않는다.
6. 경고에는 항상 '의도함 / 무시' 처리를 둔다.
7. 화면 문구는 한국어.

## 작업 방식
- 시작할 때 바꿀 파일 목록과 순서를 먼저 보여준다.
- SPEC에 없는 기능은 만들지 않는다. 필요해 보이면 제안만 하고 docs/TODO.md에 적는다.
- SPEC과 다르게 구현해야 하면 이유를 docs/PROJECT_STATE.md에 적는다.
- 끝낼 때: npm test와 npm run build 통과를 확인하고 docs/PROJECT_STATE.md(한 일 / 남은 일 / 알려진 문제)를 갱신한다.

## 명령어
- npm run dev — 개발 서버
- npm test — 단위 테스트
- npm run build — 빌드 확인
```

## 열린 질문

아래는 기본값을 정해 두고 진행해도 되지만, 해당 단계 전에 정하면 다시 손볼 일이 줄어든다.

- 보스 미리보기 시점: 탑뷰(현재 기본)와 횡스크롤 중 실제 게임은 어느 쪽인가? (7단계 전)
- 원고에서 이미 쓰는 장면 구분 기호가 있는가? 있으면 `splitScenes` 기본값으로 넣는다. (2단계 전)
- 독자 지표 기본 항목을 노벨피아에서 실제로 보이는 지표 이름으로 맞출까? (3단계 전)
- 시대 프리셋(조선 전기·중기·후기)의 연도 구분을 어느 기준으로 할까? (4단계 전)
- 데스크톱 앱 전환은 언제, 무엇으로(Tauri 또는 Electron) 할까? (9단계 이후)
